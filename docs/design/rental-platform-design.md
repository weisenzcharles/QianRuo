# 租赁项目设计文档

版本：V3.0（公开需求基线）
更新日期：2026-10-19

本文是迁若租赁平台的总体产品与系统设计，作为公开维护的 Markdown 文档持续更新。需求差异见[1.0 需求基线与实施差异](./requirements-baseline-and-gaps.md)，当前实现进度见[开发进度快照](../development-progress.md)，运行边界见[项目架构图](./architecture.md)。订单状态和列表操作规则见[商户订单流程与操作状态说明](./merchant-order-workflow-and-status.md)。

## 1. 产品定位

迁若是面向租赁商户的多维订单与库存协同平台，围绕“商户入驻、商品建档、订单录入、库存预测、仓库作业、物流履约、归还验机、售后完结、资金与证据留存”形成闭环，并通过联盟、订单大厅、小程序、免押和周转市场扩展跨主体协作。

系统不只是订单录入工具，还承担以下职责：

- 以单台 SN、配件 ID、套餐 BOM 和仓库为基础建立可追溯库存。
- 以订单租期和物流节点预测未来 30 天每日可用库存。
- 让平台、商户、员工、仓库和客户在各自权限边界内完成协作。
- 通过不可变日志、合同、协议、财务流水和证据文件支撑合规与纠纷处理。
- 通过增值服务、物流服务、分账、免押、联盟和信息发布形成商业化能力。

## 2. 产品边界

### 2.1 平台负责

- 平台用户、角色、菜单、部门和操作审计。
- 商户注册审核、认证资料、会员类型、接单资格、冻结、黑名单和信用治理。
- 协议版本、全局商品标准、增值服务、支付/发票/接口/风控等全局参数。
- 全平台会员、订单、库存、物流、售后、财务、城市和商品趋势分析。
- 客服工单、售后介入、联盟纠纷、保证金冻结、合同证据和违规内容下架。
- 数据备份、容量监控、业务告警和审计归档。

### 2.2 商户负责

- 本主体员工、角色、菜单和仓库权限。
- 店铺、来源、上门时间、库存阈值、展示方式、小程序和联系方式设置。
- 商品、配件、SN、套餐、仓库、订单、物流、归还验机、售后和盘点。
- 内部工作任务、质检评分、通知、私有知识库、操作记录和回收站。
- 本商户联盟、订单大厅、赔付模板、增值服务、物流和财务台账。

### 2.3 平台明确不负责

- 周转市场不承接买卖支付、交易担保或交易结算。
- 会员自主赔付条款由双方约定，平台只提供展示、下架、调解和证据载体。
- 未经双方确认，平台不能从履约保证金中强制扣款。
- 套餐不是独立实物库存，不能脱离商品和配件库存单独增减。

## 3. 用户与权限体系

| 用户 | 主要能力 | 核心限制 |
| --- | --- | --- |
| 平台超级管理员 | 全局配置、协议、认证、审计、财务、风控和明文敏感数据 | 高风险操作全部审计，日志不可删除 |
| 平台运营 | 商户审核、公告、内容治理、经营分析 | 无财务扣款和敏感数据批量导出权限 |
| 平台财务 | 账户、分账、提现、发票和财务报表 | 不维护商户订单和库存业务数据 |
| 平台售后/客服 | 工单、售后、纠纷材料和处理时间线 | 扣款、退款和冻结需独立权限或复核 |
| 商户所有者 | 本主体全部菜单、仓库、员工和业务数据 | 不可访问其他商户数据 |
| 商户管理员 | 被授权的员工、角色、仓库和业务配置 | 权限不超过所有者授予范围 |
| 商户财务 | 本主体收入、增值账户、发票和账单 | 不操作发货、SN 删除和员工权限 |
| 仓库员工 | 授权仓库订单、备货、扫码、验机和盘点 | 默认看不到其他仓库和完整财务数据 |
| 普通员工 | 录单、备注、视频和分配任务 | 客户敏感字段按权限脱敏 |
| 客户/访客 | 手机号或微信验证后查询自己的订单、归还和视频 | 只能访问手机号匹配的未完结订单，不能修改归还仓 |

商户主体按业务资格分为个人会员、普通企业会员和入驻会员。会员类型决定互助订单和小程序散客单的承接资格，但不能替代用户角色、菜单和仓库权限。

## 4. 端与服务设计

### 4.1 平台端

`admin-web` 面向平台内部人员，使用 `X-Client-Type: platform` 和 `/admin/**` 平台系统命名空间。平台租赁治理接口应使用独立的平台业务前缀，不调用商户 Controller。

### 4.2 商户端

`merchant-web` 面向商户及员工，使用 `X-Client-Type: merchant`，所有接口位于 `/merchant/**`。登录态由服务端写入 `tenant_id`、`member_id`、商户身份和仓库范围，业务请求不得信任前端传入的隔离字段。

### 4.3 客户端与开放入口

客户通过微信小程序、公众号或 H5 完成手机号验证、协议确认、订单查询、归还物流下单和视频查看。开放接口使用短期会话和独立限流，不复用商户后台令牌。

### 4.4 后端领域边界

- `platform-service`：平台身份、商户治理、协议、全局配置和平台审计入口。
- `merchant-service`：商户身份、角色菜单、商户上下文、个人资料、设置和商户操作日志。
- `rental-business`：商品、套餐、SN、仓库、订单、库存、核销和售后。
- `rental-logistics`：物流下单、路由、时效、天气、客户归还和承运商适配。
- `rental-finance`：账户、不可变流水、保证金、分账、提现、发票和增值服务。
- `rental-operations`：工作任务、内部通知、知识库、工单、合同和证据留存。
- `rental-alliance`：联盟关系、共享库存、定向订单、公众池和纠纷协作。
- `rental-market`：周转信息、私信、关注、举报和信息发布保证金。

`rental-business` 已建立独立 Maven 服务、Nacos 服务名、端口和数据库账号，当前只提供服务探活与接口边界；商品、套餐、SN、仓库、订单、库存、核销和售后接口必须继续在该服务内按领域实现。Controller、数据所有权和接口契约不能重新塞回平台或商户身份服务。

## 5. 核心功能架构

### 5.1 入驻、认证与协议

- 手机号验证码提交商户资料，状态进入待审核；驳回后通过同一手机号查询、修改并重新提交。
- 注册成功后立即幂等开通商户所有者；未审核时可通过手机号验证码登录并进入默认只读预览，审核通过后开放完整业务权限，首次验证码登录后进入独立初始化密码页。
- 认证材料包含身份证、营业执照、负责人芝麻分截图和人脸核验结果；当前已完成认证版本、材料、会员类型、接单资格及变更历史，材料及审核记录永久留档。
- 用户服务协议、隐私政策、物流免责协议、访客告知和互助协议独立版本化，可按网页/小程序配置生效范围。
- 新协议生效后，旧用户下一次进入对应终端必须确认具体版本后才能继续。

### 5.2 首页与我的工作台

- 首页支持所有仓库或授权仓库筛选，展示今日待发、待归还、预计到库、签收、晚到、售后，及明日待寄、逾期、月订单和营收指标。
- 商品收益分析按主商品统计库存、出租次数、租金、采购/维修成本和投入产出比。
- 租赁地图只展示城市级聚合，不暴露客户精确地址。
- 所有商户业务页面提供“我的工作台”，承载管理任务、个人任务、完成说明、超时提醒、质检备注、员工已阅和每日评分。
- 工作台同时展示未来 30 天库存小于等于 1 的日期和商品，数据来自库存快照而非前端计算。

### 5.3 订单中心

- 支持手工录入和复制文本解析；图片识别保留为后续能力。
- 姓名和手机号至少填写一个，品牌型号使用平台标准库，商户可配置常用范围。
- 录单时检查租期内可接单库存和总库存，并根据收货地址、仓库库存、调货能力和物流时效推荐发货仓与上门时间。
- 订单保存编辑前后值、抽检批注、已阅人和备注；抽检后置顶，员工已阅后取消置顶。
- 支持 SN 后绑定、系统/人工快递单、发货视频、转寄、跨仓归还、归还验机、售后、打印面单/码和可完结队列。
- 商户只能按筛选条件导出自己录入的订单；互助订单和外部小程序派单按规则脱敏且禁止批量导出。

### 5.4 商品、仓库与库存

- 平台统一维护全部层级的产品分类和标准品牌型号；商户只能从平台正常分类中选择多个经营分类，商品、型号和套餐等商户业务只展示并使用已选范围。
- 主商品强制商品编号；配件支持逐件 ID 和总数模式，总数模式也要生成可追踪虚拟 ID。
- 套餐是版本化录单模板，不形成独立实物库存；BOM 按排他资源池表达真实商品与配件约束，订单创建时展开为资源池预占。
- 通用配件只进入一个共享资源池，再通过关系表关联多个兼容型号；单套餐独立可组数可以展示但不能跨套餐直接求和。
- 商户可通过版本化容量方案在共享约束内任意切换套餐额度，例如在 `Pocket 3/Pocket 4` 的 `5+10` 与 `10+5` 之间原子切换，不移动或复制实物库存。
- 预计库存按未来 30 天逐日独立重算，并能穿透到订单、物流、SN 和异常原因。
- 库存阈值支持全局百分比、单型号百分比和保护个数，百分比只向上取整。
- 智能仓调、智能转发和自动仓调只给出候选方案，最终由有权限人员确认。

### 5.5 核销、物流与时效

- 商品码支持入库、租赁出库、出售/临时出库和连续盘点，异常只展示异常清单。
- 快递码优先匹配已录单号；未录单号时按手机号首尾、姓氏、仓库地址和当日候选订单匹配，冲突时人工选择。
- 顺丰和京东为主路由，分别执行全站 10 次/秒限流；超限排队到下一秒并返回查询中状态。
- 快递 100/快递鸟作为次路由；美团用于跑腿；天气在发货日前一日 13:00-15:00 分批查询。
- 历史线路时效形成样本库，成熟后可用于初选，发货前仍由承运商接口复核。

### 5.6 客户小程序、公众号与免押

- 手机号验证码或微信授权仅匹配该号码的未完结订单；协议必须由客户主动勾选。
- 客户可查看订单、物流、发货/拆箱视频、使用手册和商户联系方式，并从订单发起归还物流服务。
- 归还仓由订单锁定，客户不可修改；客户可修改自己的取件位置和联系信息。
- 商户会员可在小程序上传发货视频并使用扫码能力。
- 免押包括人脸认证、合同模板、补充协议、免押策略、免押码、预授权和完结后 48 小时内自动解冻。

### 5.7 内容、任务与回收站

- 商户内部通知仅对本主体员工或指定员工组可见，支持生效/下线、置顶、附件和已读记录。
- 私有知识库支持多级分类、富文本、PDF/图片/视频、员工组权限、置顶和阅读统计；历史版本保存 3 年。
- 平台超级管理员仅在合规治理权限下查看和下架违规内容，不能修改或删除商户原文。
- 商户编辑/删除操作保存原内容；普通删除进入 30 天回收站，可按条恢复并记录恢复日志。

### 5.8 售后、工单、联盟与市场

- 所有需人工审核事项进入统一客服工单，包括认证、售后、开票、赔付、退款和内容申诉。
- 联盟可按成员配置商品可见范围、可租库存比例和汇总/成员视图，默认只共享商品编号库存，不共享套餐库存。
- 定向订单可拒绝后回到联盟公众池；接单前确认平台协议和赔付规则，履约中客户信息按阶段脱敏。
- 纠纷只冻结预估赔付额度，调解 90 天，到期自动解冻；双方共同确认后才能扣款。
- 周转市场只提供标准化信息、意向、私信、举报和风控，不提供交易支付。

### 5.9 财务、商业化与经营分析

- 商户入驻支持付费注册和邀请码注册。付费注册在支付确认后开通账号；邀请码注册原子核销邀请名额后直接完成注册。
- 商户等级独立配置月完成订单、库存数量、邀请人数和注册费用要求，邀请码与邀请关系通过唯一索引防止重复统计。详细设计见《商户注册等级与邀请推广设计》。

- 增值充值账户、履约保证金账户、租金/分账账户分离，所有资金变化追加不可变流水。
- 平台统计已开票和无票收入、退款、净额、支付方式及红冲；同一订单只允许成功开票一次。
- 分账、提现和资金到账分别建台账并接受平台审核；手续费和通道流水可追溯。
- 商业化包括会员套餐、存储包、通知包、信息发布、物流服务、推广、免押和第三方风控。
- 城市、会员、商品、订单、库存和物流指标由统一口径的聚合任务生成，支持日/月/季/年筛选和报表导出。

## 6. 数据与安全设计

### 6.1 数据所有权

- 平台 IAM 数据归 `ry-cloud`。
- 商户主体、认证、商户用户、角色菜单、平台分类与标准型号、商户经营选择和治理配置归 `ry_rental`。
- 仓库、商品、SN、配件、套餐、库存、客户、订单、物流、售后和执行面流水归 `ry_business`，由 `rental-business` 独占。
- `ry_rental` 中曾与 `ry_business` 同名的 14 张订单、商品、仓库和库存核心表已经完成核对和退役，不是第二事实源，也不得重新创建；设备照片、订单编辑日志、库存快照、库存盘点和调货单也已按执行面迁移脚本完成收口。
- 数据库与表的完整归属、跨服务访问规则和收口步骤见[`ry_rental` 与 `ry_business` 数据库边界设计](./rental-database-boundaries.md)。
- 协议、认证材料、工作任务、知识库、工单、纠纷冻结、资金账户、分账提现、发票和运维事件按[实施差异](./requirements-baseline-and-gaps.md)新增表组。

### 6.2 安全不变量

- 平台和商户 Controller、权限码、菜单、令牌与缓存命名空间完全分离。
- 商户查询强制 `tenant_id + member_id`，仓库动作再校验 `warehouse_id`。
- 所有 Controller 接口的成功、失败和查询操作统一入库审计；客户敏感数据默认脱敏，密码、令牌、证件和支付信息不写入日志明文。
- 所有应用表统一使用 `is_delete` 标记软删除，运行时 MyBatis 禁止执行物理 `DELETE` 和 `TRUNCATE`，商户删除 SQL 仍必须带可信 `tenant_id + member_id`。
- 审计日志不可编辑删除，至少保留 3 年；未办结纠纷和争议证据永久保留。
- 资金流水、库存流水、协议版本和合同证据采用追加式记录，不允许覆盖历史。

### 6.3 非功能要求

- 订单、SN、库存预占、资金扣减、冻结和幂等回调必须事务化并防重复。
- 外部接口通过统一适配层处理签名、超时、重试、限流、熔断、降级和调用日志。
- 数据库每日自动备份并保留 7 天；审计和财务日志支持按月打包。
- 支付回调失败、消息失败、存储不足、任务失败和外部接口持续异常生成后台告警。
- 文件使用私有存储和临时访问 URL，容量变化写入配额流水；删除商户文件不影响平台合规留存副本。

| 协议、任务、回收站、知识库、工单、资金账户、分账提现、发票、接口治理、运维事件 | 已完成当前平台/商户治理范围；合同证据、访客/小程序完整链路、支付渠道和部分运维自动采集仍需补齐 |

任何“完成”判断必须同时验证前后端流程、数据隔离、权限、状态机、审计、异常分支和部署环境，不能以页面存在或 SQL 已创建代替。
