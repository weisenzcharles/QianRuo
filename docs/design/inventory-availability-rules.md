# 库存概览与剩余库存计算规则

更新日期：2026-09-29

## 1. 适用范围

本文定义商户端“数据 > 库存概览”的库存口径。页面支持按“型号”或“套餐”查看，并支持用户选择展示未来 1-30 天的数据；默认展示未来 30 天。

接口：`GET /merchant/inventory/overview`

参数：

| 参数 | 说明 |
| --- | --- |
| `mode` | `model` 按型号，`package` 按套餐 |
| `keyword` | 型号模式按型号、商品名称或品牌筛选；套餐模式按套餐名称或套餐编码筛选 |
| `days` | 展示天数，取值 1-30，缺省为 30；超出范围时服务端限制在 1-30 |

## 2. 统一定义

- **总库存**：商户库存汇总中同一统计对象的 `total_quantity` 合计。
- **当前可用库存**：商户库存汇总中同一统计对象的 `available_quantity` 合计。该值由逐件库存单元状态或数量库存余额维护，不直接根据订单反推。
- **有效订单**：订单未软删除、属于当前商户，且订单状态不是“已取消”或“已完成”的订单。当前状态兼容数字编码 `50`（已完成）、`80`（已取消）和历史字符串值 `completed`、`cancelled`；有效订单会在订单租期覆盖的每一天计入占用。
- **预测日**：从数据库当前日期开始，连续生成用户要求的天数，包含今天。例如 `days=3` 时返回今天、明天和后天。
- **预计剩余可用**：某预测日的当前可用库存扣除该日有效订单占用后的结果，最低按 0 展示。

每个预测日都独立以当前库存为基线计算，不使用前一天的预计结果继续扣减，避免同一订单被跨天重复累计。

## 3. 按型号计算

### 3.1 统计范围

按商户和登录成员隔离，只统计未删除的商户库存及其未删除商品。商品通过 `model_id` 聚合；型号名称优先取 `model_name`，为空时取商品名称；品牌取该型号下商品品牌的非空最大值。

### 3.2 计算公式

```text
型号当前可用 = Σ ry_rental_merchant_inventory.available_quantity

型号某日订单占用 = Σ ry_rental_order_item.quantity
  条件：
    订单与当前商户匹配且未删除
    订单状态 NOT IN (50, 80, 'cancelled', 'completed')
    订单明细未删除
    订单明细商品的 model_id 等于当前型号
    预测日 BETWEEN lease_start_date AND lease_end_date

型号预计剩余可用 = MAX(型号当前可用 - 型号某日订单占用, 0)
```

当前页面同时返回该型号的总库存、预测日期、型号名称、品牌和预计剩余可用。仓库维度暂未在库存概览中拆分，库存基线会合并当前商户所有有效仓库的汇总值。

## 4. 按套餐计算

### 4.1 统计范围

只统计当前商户启用且未删除的套餐，以及该套餐当前生效、未删除的版本和必需组件。套餐不维护独立实物库存，库存由组件可组装能力推导。

### 4.2 当前可组装量

对套餐每个必需组件，先按组件绑定的商品汇总当前可用库存，再除以该组件的需求数量并向下取整；套餐当前可组装量取所有组件结果的最小值。

```text
组件当前可组装量 = FLOOR(Σ 组件商品.available_quantity / 组件.required_quantity)

套餐当前可组装量 = MIN(所有必需组件的组件当前可组装量)
```

这意味着公共配件会自然形成约束。例如套餐需要 1 台设备和 2 块电池，设备可用 10 台、电池可用 15 块，则套餐当前可组装量为 `MIN(10, FLOOR(15 / 2)) = 7`。

### 4.3 预测日公式

```text
套餐某日订单占用 = Σ ry_rental_order_item.quantity
  条件：
    订单与当前商户匹配且未删除
    订单状态 NOT IN (50, 80, 'cancelled', 'completed')
    订单明细未删除
    订单明细 package_id 等于当前套餐
    预测日 BETWEEN lease_start_date AND lease_end_date

套餐预计剩余可用 = MAX(套餐当前可组装量 - 套餐某日订单占用, 0)
```

套餐的每个预测日同样独立使用当前生效 BOM 和当前可用库存计算，再扣除覆盖该日的有效套餐订单。

## 5. 边界和展示规则

1. `days` 小于 1 按 1 天处理，大于 30 按 30 天处理；前端输入控件也限制为 1-30。
2. 没有库存的型号或没有完整有效 BOM 的套餐不会产生可用的正数；套餐组件库存为空时，套餐可组装量为 0。
3. 订单占用超过当前可用库存时不返回负数，统一返回 0；数据异常仍应通过库存和订单业务流水排查。
4. 订单租期的开始日和结束日均包含在占用范围内。
5. 当前实现按订单明细数量扣减。逐件 SN 的占用明细、仓库调拨、预计到库、维修归还和保护库存等履约事件尚未进入该概览 SQL，后续接入时必须同步扩展公式和本文档。
6. 已取消、已完成订单不占用预测库存；服务端同时兼容当前数字状态 `80`、`50` 与历史字符串状态 `cancelled`、`completed`，其他未完成订单即使当前尚未发货，只要租期覆盖预测日，仍会计入该日占用。

## 6. 示例

某型号当前可用库存为 10：

| 订单 | 租期 | 数量 |
| --- | --- | ---: |
| A | 今天-明天 | 3 |
| B | 后天-大后天 | 4 |
| C | 今天-后天，已取消 | 2 |

则预计剩余可用为：今天 `7`、明天 `7`、后天 `6`、大后天 `6`。订单 C 因已取消不计入。

## 7. 实现对应关系

- 服务入口：`MerchantInventoryController.overview`
- 天数限制：`MerchantInventoryService.overview`
- 型号 SQL：`MerchantInventoryMapper.xml` 的 `selectModelOverview`，订单状态通过 `excludedOrderStatuses` 参数过滤并补充订单租户条件
- 套餐 SQL：`MerchantInventoryMapper.xml` 的 `selectPackageOverview`，订单状态通过 `excludedOrderStatuses` 参数过滤并补充订单租户条件
- 前端展示：`frontend/merchant-web/src/views/merchant/data/index.vue`
