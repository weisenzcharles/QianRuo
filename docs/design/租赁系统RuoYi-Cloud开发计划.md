# 租赁系统 RuoYi-Cloud 开发计划

版本：V3.0（1.0 需求基线）
更新日期：2026-07-30
技术基线：RuoYi-Cloud 3.6.8、Java 17、Vue 3、MySQL、Redis、Nacos

本文按最新三个 1.0 Word 文档重排研发阶段。需求规则与实施差异见[1.0 需求基线与实施差异](./1.0需求基线与实施差异.md)，当前已经实现的事实见[第 1 阶段完成状态](./第1阶段完成状态.md)。

## 1. 计划原则

- 平台端和商户端用户、角色、菜单、权限、Controller、令牌和缓存命名空间彻底隔离，不提供旧路径兼容分支。
- 商户所有业务接口统一位于 `/merchant/**`，由服务端登录态提供 `tenant_id + member_id + warehouse_scope`。
- 平台治理接口使用独立平台命名空间；跨商户查询必须显式授权并审计。
- 商品、订单、库存、物流、资金、协议和证据都以状态机和不可变流水为核心，不以普通 CRUD 代替业务流程。
- 先完成数据模型、服务边界和异常规则，再批量生成基础页面；复杂状态机、库存算法和财务流水手写实现。
- 每个阶段必须同时交付迁移、后端、前端、权限、审计、测试、部署和文档，不能只交付页面骨架。

## 2. 状态定义

| 状态 | 含义 |
| --- | --- |
| 已完成 | 已实现并通过当前仓库记录的构建、接口或部署验证 |
| 进行中 | 已有部分实现，尚未满足阶段验收门禁 |
| 已建表待实现 | 数据表已存在，但业务服务、前端流程或测试尚未完成 |
| 规划 | 最新 1.0 需求已定义，当前尚未完整建模或编码 |

### 3.2 目标业务模块

| 模块 | 业务所有权 | 初期实现策略 |
| --- | --- | --- |
| `rental-business` | 商品、SN、配件、套餐、仓库、订单、库存、核销和售后 | 优先新增独立服务，内部按领域包拆分 |
| `rental-logistics` | 承运商、下单、路由、时效、天气、客户归还 | 可先作为独立模块，与业务服务只通过契约交互 |
| `rental-finance` | 资金账户、流水、冻结、分账、提现、发票和增值服务 | 先完成模型评审再编码，禁止借用单余额字段过渡 |
| `rental-operations` | 工作任务、通知、知识库、客服工单、协议、合同和证据 | 可按工作协作、内容、工单三个子模块实现 |
| `rental-alliance` | 联盟关系、共享库存、协作订单和纠纷关联 | 主流程稳定后独立开发 |
| `rental-market` | 周转信息、私信、关注、举报和信息发布保证金 | 后置开发，不实现交易支付 |
| `rental-integration` | 顺丰、京东、快递次路由、天气、微信、支付宝、e签宝和风控适配 | 初期为共享适配模块，禁止业务代码直连第三方 SDK |

目标模块可以分阶段上线，但不得把租赁业务重新写入 `platform-service` 或 `merchant-service`。身份服务只提供可信上下文和授权，业务数据由所属领域服务维护。

## 4. 全局工程任务

### 4.1 安全与隔离

- 所有租赁业务表包含 `tenant_id + member_id`；商户 Mapper 的查询、导出、修改、删除和批量授权都必须使用两个隔离键。
- 仓库相关操作统一调用 `MerchantContextUtils.checkWarehouseAccess(warehouseId)` 或等价公共守卫。
- 客户姓名、手机号、地址、芝麻分、身份证和营业执照默认脱敏；明文查看、导出和复制单独授权并记录审计。
- 平台、商户、客户开放接口使用不同权限域和会话；禁止通过请求参数切换身份体系。
- 登录、验证码、物流查询、上传、市场发布、私信、举报、支付回调和第三方接口按用户、IP、设备、租户多维限流。

### 4.2 数据与事务

- 订单创建、库存预占、SN 绑定、发货、归还、完结、调货、盘点、资金冻结和扣款必须事务化。
- 关键请求使用幂等键和唯一约束；支付、物流和授权回调保存提供方事件 ID，重复回调返回原结果。
- 库存与财务只通过追加流水变化；禁止直接覆盖历史余额、SN 状态或财务记录。
- 所有时间统一使用 Asia/Shanghai 业务时区；数据库、JVM、JSON 和前端展示格式保持一致。
- 全部应用表统一 `isdeleted` 软删除，启用 MyBatis 物理删除保护并修改代码生成模板；不可恢复的审计、财务、合同和争议证据不进入普通删除流程。

### 4.3 外部接口治理

- 统一定义 provider、能力、优先级、签名、超时、重试、限流、熔断、降级和调用日志。
- 顺丰和京东分别执行全站 10 次/秒限流，超出请求排到下一秒并返回可轮询的查询中状态。
- 快递 100/快递鸟只作为次路由；所有降级必须记录原因，不能静默返回伪造时效。
- 天气查询按发货日前一日 13:00-15:00 分片执行；历史线路时效由定时任务聚合。
- 第三方密钥只来自配置中心或密钥管理，不写入数据库明文字段、源码或前端环境变量。

### 4.4 可观测与合规

- 平台管理员、商户员工和访客操作日志分表或分存储，权限与留存策略独立。
- 审计日志不可编辑删除，至少保留 3 年；未办结纠纷、认证材料和争议证据按规则永久保留。
- 支付回调失败、消息失败、定时任务失败、存储不足和外部接口连续异常生成告警事件。
- 数据库每日自动备份，备份包保留 7 天；审计和财务日志支持按月打包导出。
- 所有 Controller 接口通过通用切面入库审计，输出 trace ID 和 HTTP 状态码；外部接口调用、异步任务和工单事件可串联追踪。

## 5. 前端任务拆分

### 5.1 商户端

- 首页与全局工作台：仓库筛选、今日/汇总指标、库存风险、任务、完成说明、抽检和评分。
- 订单中心：录单、复制解析、库存/时效校验、订单详情、编辑记录、批注已阅、状态操作和受限导出。
- 商品与仓库：标准型号、常用型号、商品、SN、配件、套餐、仓库、库存快照、调货、盘点和扫码。
- 物流与客户服务：快递下单、路由、时效、归还物流、视频、客户小程序和公众号配置。
- 员工协作：用户、角色、菜单、仓库权限、任务、内部通知、知识库、操作记录和回收站。
- 商业与协作：账户、发票、增值服务、联盟、订单大厅、赔付模板、免押和市场。

### 5.2 平台端

- 平台治理：协议版本、商品标准、会员权限模板、全局参数、增值服务和消息通知。
- 商户与认证：注册审核、材料、会员类型、接单资格、信用、黑名单、冻结和申诉。
- 全局业务：订单大厅、库存、订单、物流、售后、客服工单、合同和证据。
- 财务与风控：账户、分账、提现、开票、红冲、保证金、纠纷冻结、退款和异常账单。
- 经营与运维：城市/商品趋势、活跃度、推广、审计、容量、备份、告警和任务监控。

### 5.3 共享前端能力

- 脱敏文本、明文查看审计、仓库选择器、SN 选择器、商品套餐选择器、状态时间线和库存穿透。
- 私有上传、附件预览、协议确认、富文本安全渲染、版本对比和审计日志抽屉。
- 统一的金额、日期、手机号、证件、枚举和错误码展示；禁止页面自行计算核心库存或财务口径。

## 6. 数据库演进计划

### 6.1 现有表继续使用

当前 `ry_rental` 的 49 张表继续承载商户身份、仓库、商品、SN、套餐、客户、订单、库存、物流、媒体、售后、基础财务、联盟、市场、授权、分享、免押、幂等和审计。

### 6.2 新增表组

- 协议：协议、版本、接受记录。
- 认证信用：认证批次、认证材料、信用事件、黑名单记录。
- 工作协作：任务、指派、提交、质检评分、回收站。
- 内容：内部通知、受众、已读，知识分类、文章、版本和阅读记录。
- 工单证据：客服工单、分配、事件、附件，合同模板、订单合同和签约证据。
- 财务：资金账户、账户流水、冻结记录、分账、结算、提现、开票申请和红冲。
- 接口运维：提供方、调用日志、历史时效样本、容量流水、告警事件和备份记录。
- 访客：访客会话、协议接受和访客操作日志。

每个表组先提交 ER 图、字段字典、唯一约束、租户索引、状态枚举、留存策略和迁移回滚说明，再编写正式迁移。

## 7. 分阶段开发计划

### 第 0 阶段：工程和部署基线（已完成）

- 建立后端、双前端、MySQL、Redis、Nacos、文件和任务服务的一键部署链路。
- 统一 Java 17、Node、MySQL、时区、镜像和环境变量基线。
- 验收：本地 Docker 可重复启动，基础服务健康检查通过，部署不强制重复拉取已有镜像。

### 第 1 阶段：双端身份、商户入驻与权限骨架（已完成）

- 平台与商户用户、角色、菜单、Controller、会话和接口命名空间彻底拆分。
- 完成公开入驻、平台审核、驳回重提、审核后开通管理员、首次验证码登录和初始化密码。
- 完成商户上下文、仓库范围、商户用户权限、会话失效和商户操作日志。
- 验收结果见[第 1 阶段完成状态](./第1阶段完成状态.md)。

### 第 2 阶段：治理基础与业务主数据（3 周，下一阶段）

- 协议版本与接受记录、商户完整认证材料、三类会员和接单资格。
- 平台多级产品类目与商户经营类目选择已完成；继续实现品牌型号、商户常用型号、仓库、商品、SN、配件、排他资源池、版本化套餐 BOM、可切换容量方案和来源设置。
- 文件私有访问、配额流水、数据字典、统一错误码和 OpenAPI 契约。
- 完成租赁业务服务骨架，所有基础 CRUD 接入商户/仓库隔离和平台只读治理接口。
- 验收：跨商户/跨仓库测试全部拒绝；协议重新确认生效；认证材料和审核历史可追溯；主数据可导入导出且有审计；共享手柄容量可在 `5+10` 与 `10+5` 间切换，`10+10` 被拒绝。

### 第 3 阶段：订单主流程 MVP（4 周）

- 手工录单、复制文本解析、商品/套餐明细、库存区间校验、仓库选择、SN 后绑定和编辑记录。
- 备货、发货、物流单号、视频、租用、归还、验机、可完结、售后、取消和追回状态机。
- 抽检批注、置顶/已阅、备注和受限导出。
- 验收：从录单到完结闭环可重复演示；状态不可非法跳转；库存和订单流水一致；互助/外部订单脱敏且不可批量导出。

### 第 4 阶段：库存预测与仓库作业（3 周）

- 未来 30 天商品/套餐预计库存逐日独立重算、实时空闲、物流库存和库存穿透。
- 全局/型号百分比和保护个数、告警、智能仓调、智能转发和人工确认。
- 商品码入出库、快递码匹配、连续盘点、异常库存和跨仓归还。
- 验收：任一库存数字可追溯至 SN、订单和流水；快照重跑结果一致；并发预占不产生负库存。

### 第 5 阶段：物流、时效与客户入口（3 周）

- 顺丰/京东主路由、次路由回退、全站 10 次/秒队列、历史时效和天气批处理。
- 物流下单、取消、路由同步、晚到/丢失赔付和异常告警。
- 客户手机号/微信验证、协议确认、订单查询、视频、归还物流和商户小程序能力。
- 验收：客户只能访问匹配订单，归还仓不可修改；限流压测符合规则；第三方重试和回调具备幂等。

### 第 6 阶段：商户协作与内容（2-3 周）

- 全局工作台、管理/个人任务、完成说明、超时提醒、抽检、评分和日报。
- 内部通知、员工分组、置顶、生效/下线、已读记录。
- 私有知识库、多级分类、附件、版本、阅读权限、阅读统计和违规下架。
- 30 天回收站和按条恢复，编辑/删除前后值记录。
- 验收：内容只对本商户授权员工可见；平台普通管理员不可看正文；版本和恢复流程可追溯。

### 第 7 阶段：平台工单、合同、财务与风控（4 周）

- 统一认证、售后、开票、赔付、退款和内容申诉工单。
- 订单合同、协议版本、签约人/IP/时间和证据文件。
- 增值余额、履约保证金、租金/分账账户、不可变流水、冻结、解冻和扣款。
- 分账、结算、提现、开票申请、补票、红冲和财务报表。
- 验收：资金账户不能混用；同订单不能重复开票；冻结额度和 90 天解冻规则通过自动化测试；所有高风险动作有审计。

### 第 8 阶段：联盟、订单大厅与纠纷（3 周）

- 联盟关系、短信确认、商品可见范围、共享比例、汇总/成员库存视图。
- 定向订单、公众池、接受、拒绝、转派、发货和完成。
- 赔付模板、纠纷证据、双方确认、保证金定额冻结和平台调解。
- 验收：联盟外不可读取共享库存；套餐库存不共享；单方未确认时不能扣款；到期自动解冻。

### 第 9 阶段：商业化、免押、推广与市场（3-4 周）

- 会员套餐、存储包、通知包、信息发布和物流服务计费。
- 免押码、人脸、合同、预授权、风险提示和完结后 48 小时解冻。
- 推广规则、推广员、优惠券、佣金冻结和退款冲回。
- 周转市场帖子、筛选、私信、关注、举报、保证金和降权。
- 验收：市场无交易支付；计费和退款都有不可变流水；推广反作弊规则生效。

### 第 10 阶段：经营分析、运维与上线加固（持续）

- 商户首页、平台全局、城市、商品热度、会员活跃、订单、库存、物流和财务指标统一口径。
- 每日备份、月度日志包、容量监控、支付/消息/任务/存储告警。
- 性能压测、容量评估、漏洞扫描、权限回归、灾备恢复和灰度发布。
- 验收：报表可追溯到原始数据；备份可恢复；核心链路达到约定 SLO；安全与越权用例全部通过。

## 8. 阶段门禁

每个阶段关闭前必须满足：

1. 数据库迁移在全新库和已有库都能执行，具备幂等或明确的一次性约束。
2. 后端单元/集成测试覆盖正常、越权、并发、重复请求和关键异常分支。
3. 平台端、商户端和开放端只调用各自命名空间，网关路由与权限码一致。
4. 前端生产构建通过，桌面和常用移动视口无字段遮挡、溢出或流程死路。
5. Docker 本地部署健康检查通过，服务日志无持续异常，外部依赖故障有可验证降级。
6. 操作日志、业务流水、监控和告警能够定位一次完整请求。
7. 设计、规格、路由、迁移和完成状态文档同步更新。

2. 建立 `rental-business` 服务骨架及平台/商户双接口边界。
3. 实现主数据迁移、商户/仓库隔离守卫和基础 CRUD。
4. 完成文件私有访问、配额和主数据导入导出审计。
5. 以跨商户、跨仓库、协议生效和认证留痕用例作为第 2 阶段首批自动化验收。
