### 外部库存同步当前契约

- 只读快照：第三方使用 `GET /open/inventory/snapshot`，令牌只需 `inventory:read` 范围。
- 外部预占：第三方使用 `POST /open/inventory/reservations`，令牌必须同时具备 `inventory:reserve` 范围，并提供 `X-Inventory-Token`、`X-Request-Id`、`X-Inventory-Signature`。
- 外部释放：第三方使用 `POST /open/inventory/reservations/{reservationNo}/release`，签名原文为“请求幂等号 + 换行 + release + 换行 + 预占单号”；预占请求签名原文使用固定字段顺序，见 `MerchantExternalInventoryReservationCommand.canonicalValue()`。
- 外部预占拥有独立来源、令牌、外部订单标识、商品和数量快照，复用库存锁、数量扣减和序列号状态迁移；它不会伪造正式订单，也不会让第三方直接改写库存事实。
- 外部正式订单：第三方使用 `POST /open/orders`，令牌必须具备 `order:create` 范围，且令牌创建时配置 HTTPS 回调地址；请求必须引用同一令牌下仍处于已预占状态的 `reservationNo`，服务端从预占记录恢复仓库、套餐/商品和数量后创建正式订单，同一令牌下的 `externalOrderNo` 幂等。
- 外部订单创建成功后，事务内写入回调出站事件；统一调度任务通过 HTTPS + HMAC 发送“订单已创建”回调。订单后续状态变化也写入同一出站队列，失败按退避策略重试并记录送达/耗尽状态。

## 2. 统一术语

| 新版文档用语 | 工程统一用语 | 说明 |
| --- | --- | --- |
| 会员 | 商户主体（member） | 完成平台注册、认证并经营租赁业务的个人或企业主体 |
| 会员后台 | 商户端（merchant-web） | 商户管理员及员工使用的业务后台 |

## 4. 不可变业务规则

### 4.1 身份与数据隔离

- 平台用户、商户用户、角色、菜单和接口命名空间不得兼容或回退复用。
- 商户业务请求必须从服务端登录态读取 `tenant_id + member_id`，涉及仓库时再校验仓库范围；前端提交的隔离字段不可信。
- 平台跨商户查看必须由独立权限控制，客户手机号、地址、芝麻分和身份材料默认脱敏；查看明文和导出必须记审计。
- 商户类型分为个人会员、普通企业会员、入驻会员；接互助订单和接小程序散客单的资格独立配置，只有完成企业或个体工商户认证的主体可开通接单权限。

### 4.2 库存与订单

- 未来 30 天预计库存按“每天独立重算”生成，不能沿用前一日结果递推。
- 商品预计库存基线为：总商品数 - 当日待发货 - 租用中 - 售后 - 已逾期 - 逾期归还 + 预计到库；实现时必须将每一项落到可追溯订单和 SN。
- 套餐只作为 BOM 模板，套餐可用量由同日商品和配件约束推演，不能维护独立实物库存。
- 库存保护支持全局最低百分比、单型号最低百分比和单型号保护个数；百分比结果只向上取整。
- 订单姓名和手机号至少填写一个；核心字段修改保留前后值、操作者和时间。
- 平台互助订单及外部小程序派单发货后按规则脱敏，不允许批量导出，只能逐条按权限查看。

### 4.3 物流与外部接口

- 顺丰和京东为主路由，各自全站每秒最多 10 次查询；超出请求进入下一秒队列，前端显示“查询中”，不得直接失败或绕过限流。
- 快递 100 或快递鸟作为次路由，只在主路由无法满足时使用；所有路由调用要保留提供方、请求摘要、耗时、结果和错误码。
- 发货前一日再次校验时效；历史样本足够后可优先使用历史线路时效，但仍需以承运商复核兜底。
- 发货地和收货地天气在实际发货日前一日 13:00-15:00 分批查询，避免订单页面实时批量打爆接口。
- 当前订单列表已按发货仓库市级/收件人区县 `adcode` 查询天气；行政区划表中的高德 `citycode` 仅作为快照保留。高德 API Key 由平台系统配置维护，服务端按 adcode 缓存 1 小时，未配置或调用失败时显示“待查询”。
- 订单收件人地址每次新增/编辑均追加历史快照，行政区划解析统一复用 `RegionAddressParser`；详细数据关系见[订单收件人行政区划与全局天气设计](./order-recipient-regions-and-weather.md)。

### 4.4 审计、删除与留存

- 平台与商户所有 Controller 接口均记录入库审计，日志包含终端、主体、链路 ID、HTTP 状态和耗时；高风险动作还必须记录业务前后值。
- 审计日志及关联原始文件至少保存 3 年；未办结纠纷和争议证据永久保留。
- 所有应用表统一使用 `is_delete`，运行时禁止物理删除；审计、财务、协议、合同和争议证据不开放普通删除入口。
- 商户普通删除进入回收站保留 30 天，可按条恢复；恢复必须再次校验数据归属和唯一约束。
- 知识库修改自动保存历史版本 3 年；违规下架版本永久保留，平台只能下架，不能修改或删除会员原文。

### 4.5 资金与纠纷

- 增值充值余额、履约保证金、租金/分账资金分别建账，不能互相抵扣或共用余额字段。
- 保证金只能按纠纷预计赔付额度冻结，不能无条件全额冻结；调解周期固定 90 天，到期自动解冻。
- 保证金扣款必须由双方线上确认赔付金额；任一方未确认时平台不能强制扣款。
- 同一订单只允许成功开票一次；补票、红冲和退款均通过追加记录关联原订单，禁止覆盖原流水。
- 周转市场仅提供信息展示、意向和风控，不承担交易撮合支付或结算。

| 纠纷与赔付 | `compensation_template`、`dispute_case`、`dispute_evidence`、`dispute_confirmation` | 赔付条款绑定联盟/大厅订单，纠纷绑定证据和双方确认 |
| 资金账户 | `finance_account`、`account_ledger`、`fund_freeze` | 账户按资金性质隔离，冻结/解冻/扣款追加流水 |

| 发票 | `invoice_application`、`invoice_record`、`invoice_red_flush` | 开票申请绑定消费订单，红冲关联原发票 |
| 合同存证 | `contract_template`、`order_contract`、`contract_evidence` | 订单绑定合同版本、签约人、IP、时间和证据 |
| 接口治理 | `integration_provider`、`integration_call_log`、`route_timing_sample` | 外部提供方配置、调用审计和历史线路时效 |
| 容量与运维 | `storage_quota_ledger`、`alert_event`、`backup_record` | 配额变化、异常告警和备份执行可追溯 |
| 访客审计 | `visitor_session`、`visitor_oper_log` | 客户验证码、协议、归还、支付和退款动作留痕 |

## 6. 研发优先级

### P0：进入租赁主流程前必须完成

- 协议版本与重新确认；商户完整认证材料、三类会员、接单资格和认证历史已完成当前范围。
- 业务服务统一商户/仓库上下文、敏感信息脱敏、不可变审计和统一幂等。
- 商品、仓库、SN、套餐、订单、库存流水基础模型与状态机。
- 外部接口适配规范、顺丰/京东全站限流和失败降级框架。
- 资金账户分离方案和数据库表设计评审，避免订单上线后返工财务口径。

### P1：形成可运营闭环

- 订单发货归还、预计库存、扫码核销、物流路由、客户小程序和售后工单。
- 工作任务、质检评分、编辑记录、30 天回收站。
- 知识库文章、分类、版本、附件、员工组受众、发布/下架、阅读统计、平台合规查看和违规下架记录已完成当前范围；平台不能编辑或删除商户原文。
- 平台订单/库存/会员报表、客服工单、合同存证和操作审计。

### P2：商业化与协作扩展

- 分账、提现、开票、增值服务、推广、免押和第三方风控。
- 联盟、订单大厅、赔付条款、纠纷冻结和 90 天调解。
- 周转市场、城市/商品趋势、存储套餐、完整运维告警和备份台账。
