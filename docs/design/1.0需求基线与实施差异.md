# 1.0 需求基线与实施差异

版本：V1.0 需求基线  
更新日期：2026-08-02

本文将最新三个 1.0 Word 文档转换为可执行的研发基线，并与当前代码、数据库和既有设计逐项对照。本文负责定义“做什么”和“缺什么”；当前实际运行边界以[项目架构图](./项目架构图.md)和[第 1 阶段完成状态](./第1阶段完成状态.md)为准。

## 1. 权威来源与优先级

1. `1.0-迁渃—多维订单库存管理系统.docx`：商户业务主流程、订单、库存、商品、核销、联盟、小程序和第三方接口规则。
2. `1.0-总后台-迁渃.docx`：平台治理、协议、认证、审计、财务、工单、风控、运维和经营分析规则。
3. `1.0-会员后台-迁渃.docx`：商户设置、工作安排、回收站、来源、库存、商品和联盟配置规则。
4. 当前代码、SQL、路由和部署文件：仅用于判定实现状态，不得反向覆盖上述产品规则。

当三个 1.0 文档与旧版拆分文档存在冲突时，以三个 1.0 文档为准；旧版文档仅保留历史补充价值。仍存在歧义的需求必须进入产品决策清单，不能由开发人员静默猜测。

## 2. 统一术语

| 新版文档用语 | 工程统一用语 | 说明 |
| --- | --- | --- |
| 会员 | 商户主体（member） | 完成平台注册、认证并经营租赁业务的个人或企业主体 |
| 会员后台 | 商户端（merchant-web） | 商户管理员及员工使用的业务后台 |
| 总后台 | 平台端（admin-web） | 平台运营、财务、客服、售后、风控和系统管理员使用 |
| 商户/店铺 | 商户主体及店铺资料 | 当前数据库隔离键为 `tenant_id + member_id` |
| 会员主账号 | 商户所有者（owner） | 注册后立即开通；审核前为默认只读预览，审核通过后拥有商户全部仓库和菜单权限 |
| 租客/访客 | 客户（customer/visitor） | 通过手机号、微信或小程序访问自己的订单和归还服务 |
| 商品编号/设备号 | 资产 SN（asset_sn） | 单台主商品或启用逐件管理的配件唯一标识 |
| 套餐 | 套餐模板（package_template） | 录单快捷模板，不形成独立实物库存 |

## 4. 不可变业务规则

### 4.1 身份与数据隔离

- 平台用户、商户用户、角色、菜单和接口命名空间不得兼容或回退复用。
- 商户业务请求必须从服务端登录态读取 `tenant_id + member_id`，涉及仓库时再校验仓库范围；前端提交的隔离字段不可信。
- 平台跨商户查看必须由独立权限控制，客户手机号、地址、芝麻分和身份材料默认脱敏；查看明文和导出必须记审计。
- 商户类型分为个人会员、普通企业会员、入驻会员；接互助订单和接小程序散客单的资格独立配置，只有完成企业或个体工商户认证的主体可开通接单权限。

### 4.2 库存与订单

- 未来 30 天预计库存按“每天独立重算”生成，不能沿用前一日结果递推。
- 商品预计库存基线为：总商品数 - 当日待发货 - 租用中 - 售后 - 已逾期 - 逾期归还 + 预计到库；实现时必须将每一项落到可追溯订单和 SN。
- 套餐只作为 BOM 模板，套餐可用量由同日商品和配件约束推演，不能维护独立实物库存。
- 库存保护支持全局最低百分比、单型号最低百分比和单型号保护个数；百分比结果只向上取整。
- 订单姓名和手机号至少填写一个；核心字段修改保留前后值、操作者和时间。
- 平台互助订单及外部小程序派单发货后按规则脱敏，不允许批量导出，只能逐条按权限查看。

### 4.3 物流与外部接口

- 顺丰和京东为主路由，各自全站每秒最多 10 次查询；超出请求进入下一秒队列，前端显示“查询中”，不得直接失败或绕过限流。
- 快递 100 或快递鸟作为次路由，只在主路由无法满足时使用；所有路由调用要保留提供方、请求摘要、耗时、结果和错误码。
- 发货前一日再次校验时效；历史样本足够后可优先使用历史线路时效，但仍需以承运商复核兜底。
- 发货地和收货地天气在实际发货日前一日 13:00-15:00 分批查询，避免订单页面实时批量打爆接口。

### 4.4 审计、删除与留存

- 平台与商户所有 Controller 接口均记录入库审计，日志包含终端、主体、链路 ID、HTTP 状态和耗时；高风险动作还必须记录业务前后值。
- 审计日志及关联原始文件至少保存 3 年；未办结纠纷和争议证据永久保留。
- 所有应用表统一使用 `isdeleted`，运行时禁止物理删除；审计、财务、协议、合同和争议证据不开放普通删除入口。
- 商户普通删除进入回收站保留 30 天，可按条恢复；恢复必须再次校验数据归属和唯一约束。
- 知识库修改自动保存历史版本 3 年；违规下架版本永久保留，平台只能下架，不能修改或删除会员原文。

### 4.5 资金与纠纷

- 增值充值余额、履约保证金、租金/分账资金分别建账，不能互相抵扣或共用余额字段。
- 保证金只能按纠纷预计赔付额度冻结，不能无条件全额冻结；调解周期固定 90 天，到期自动解冻。
- 保证金扣款必须由双方线上确认赔付金额；任一方未确认时平台不能强制扣款。
- 同一订单只允许成功开票一次；补票、红冲和退款均通过追加记录关联原订单，禁止覆盖原流水。
- 周转市场仅提供信息展示、意向和风控，不承担交易撮合支付或结算。

## 6. 研发优先级

### P0：进入租赁主流程前必须完成

- 协议版本与重新确认；商户完整认证材料、三类会员、接单资格和认证历史已完成当前范围。
- 业务服务统一商户/仓库上下文、敏感信息脱敏、不可变审计和统一幂等。
- 商品、仓库、SN、套餐、订单、库存流水基础模型与状态机。
- 外部接口适配规范、顺丰/京东全站限流和失败降级框架。
- 资金账户分离方案和数据库表设计评审，避免订单上线后返工财务口径。

### P1：形成可运营闭环

- 订单发货归还、预计库存、扫码核销、物流路由、客户小程序和售后工单。
- 工作任务、质检评分、编辑记录、30 天回收站。
- 商户内部通知、私有知识库、员工分组和阅读统计。
- 平台订单/库存/会员报表、客服工单、合同存证和操作审计。

### P2：商业化与协作扩展

- 分账、提现、开票、增值服务、推广、免押和第三方风控。
- 联盟、订单大厅、赔付条款、纠纷冻结和 90 天调解。
- 周转市场、城市/商品趋势、存储套餐、完整运维告警和备份台账。

## 7. 验收追踪规则

- 每个开发任务必须引用本文件中的功能域和规则编号，并在接口、迁移、测试和前端页面之间建立对应关系。
- “已建表”“已有页面骨架”“接口可返回”都不能单独判定完成；完成必须同时满足数据隔离、状态流转、权限、审计、异常处理和自动化验证。
- 产品规则发生变化时先更新三个 1.0 源文档或本基线，再更新详细规格、架构图和开发计划，禁止只在代码或聊天记录中保留决策。
