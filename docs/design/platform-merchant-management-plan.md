# 平台端商户管理能力实施计划

## 现状盘点

平台端已具备商户资料、商户用户、商户菜单、产品分类、产品型号、平台配件、平台套餐、订单渠道、协议和联盟治理入口。商户端已经具备仓库、商品、配件、套餐、库存、订单、联盟和数据页面。

当前缺口主要有两类：

1. 平台需要继续补充以商户为维度查看仓库、商品、配件、套餐、库存和订单汇总的管理视图。

财务、工单、客户服务、统计分析、消息通知和运营风控属于需求基线中的后续阶段，必须在明确业务口径和数据来源后再实现，不能为了补菜单直接伪造接口或跨库查询。

## 第一阶段：商户经营概况

### 页面

平台端“商户管理”下增加“经营概况”菜单。页面按商户分页，支持按商户名称、主体名称或商户编码查询，展示认证状态、冻结状态、仓库数、设备商品数、配件数、套餐数、库存状态数量和订单状态数量。

浏览器接口只返回页面实际使用的展示字段，不返回 `member_id`、`tenant_id` 等技术关联字段。商户名称使用店铺名称，缺失时回退到主体名称；统计没有业务记录时显示为 0。

### 服务边界

平台服务从 `ry_rental` 分页读取商户基础信息，再通过内部 Feign 调用 `rental-business`。`rental-business` 只在 `ry_business` 内聚合执行面数据。平台服务不直接访问 `ry_business`，浏览器接口也不暴露内部商户编号。

### 统计口径

| 指标 | 口径 |
| --- | --- |
| 仓库数 | 未删除且启用的仓库 |
| 设备商品数 | 未删除、启用且商品类型为设备的商品 |
| 配件数 | 未删除且启用的商户配件目录记录 |
| 套餐数 | 未删除且启用的商户套餐 |
| 库存数量 | 未删除且启用的库存汇总中的总数、可用、预占、出租、维修和损坏数量 |
| 待处理订单 | 未删除且订单状态为待发货或已备货 |
| 进行中订单 | 未删除且订单状态为运输、发货、租用、归还或售后等非完成状态 |
| 已完成订单 | 未删除且订单状态为已完成 |
| 逾期订单 | 未删除且订单状态为归还逾期/已逾期，或时效状态标记为逾期 |

## 后续阶段

### 第二阶段：平台订单基础管理增强（已完成）

平台端订单中心新增商铺、订单编码/外部单号/联系人关键词、订单状态和创建日期筛选，筛选条件在 `rental-business` 统一参数化执行，默认按创建时间倒序分页。商铺筛选支持商户编码、店铺名称和主体名称，避免只匹配店铺昵称。

平台浏览器接口改用专用最小化 VO，仅返回订单编码、商户名称、来源店铺、客户必要展示信息、租期、金额、状态和创建时间；不返回 `order_id`、`tenant_id`、`member_id` 等技术关联字段，客户电话默认脱敏。平台服务仍通过内部 Feign 读取执行面数据，不直接访问 `ry_business`。

平台订单详情已补充履约时间线、套餐快照、商品/配件明细、物流、归还验机、售后、批注和变更记录。客户电话、收件电话和收货地址默认脱敏；具备独立权限的用户可主动查看完整客户信息，接口只返回最小客户视图，且每次查看由平台操作日志留痕。

### 第三阶段：平台商户经营明细（已完成）

“经营概况”列表新增“经营明细”操作，通过商户编码打开只读抽屉，展示仓库、商品、套餐和库存四个分组。每组最多返回 200 条，避免打开详情时一次加载商户全部数据；状态、商品类型和来源统一在页面转换为业务文字。

平台服务先在 `ry_rental` 按商户编码解析可信的租户/商户范围，再通过内部 Feign 调用 `rental-business`。明细查询只访问 `ry_business`，使用专用聚合 Mapper 和传输对象；浏览器返回不含租户、商户、仓库、商品、套餐或库存技术主键，也没有新增写操作。

已增加独立的“履约与风险”治理页签。履约质量展示订单总数、待处理、进行中、已完成、逾期和售后数量；物流治理展示物流单、待完成物流和异常物流数量；风险明细展示未解除库存告警和未结联盟纠纷数量。该页签使用 `platform:merchantOverview:governance:view` 独立权限，默认仅授予平台超级管理员；统计由 `rental-business` 按 `tenant_id + member_id` 聚合，平台服务不直接访问执行面数据库。

### 待实施

1. 平台治理能力：按需求基线补充协议、资格、通知、财务、工单、统计分析和运营风控，分别确认表结构、数据权限和审计要求。
