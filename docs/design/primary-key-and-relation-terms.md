# 主键与关联字段术语规范

## 1. 目标

统一项目中主键、外键和关联字段的语义表达，避免把数据库关系字段误认为业务编码，同时保持现有接口和数据关系稳定。

## 2. 技术字段约定

- 数据库、Java、TypeScript、JSON、Mapper XML 和接口参数继续使用现有字段名：`id`、`*_id`、`Id`。
- 不新增或改名为 `unique_no`、`uniqueNo`，也不因为文案统一而修改实体属性、序列化属性、SQL 列名或关联条件。
- 物理主键、逻辑关联和索引关系保持不变；本规范不把字段改名为 `unique_no`。历史审计字段类型统一由版本化迁移 `V20260822_001__audit_user_id_types.sql` 处理，不通过修改文案或实体绕过数据库迁移。
- 外键仍按现有项目约定使用逻辑关联，不新增物理外键约束。

## 3. 语义表达

主键、外键和关联字段的注释、Javadoc、校验提示、Excel 表头、接口说明和页面展示统一使用“唯一编号”：

| 技术字段 | 统一文案 | 示例 |
| --- | --- | --- |
| `id` | 唯一编号 | 记录唯一编号 |
| `brand_id` | 品牌唯一编号 | 型号的品牌唯一编号 |
| `class_id` | 分类唯一编号 | 商品的分类唯一编号 |
| `model_id` | 型号唯一编号 | 商品的型号唯一编号 |
| `order_id` | 订单唯一编号 | 订单明细的订单唯一编号 |
| `create_by` | 创建者用户唯一编号 | 审计字段关联用户 |
| `update_by` | 更新者用户唯一编号 | 审计字段关联用户 |
| `remove_by` | 删除者用户唯一编号 | 软删除审计字段关联用户 |

## 4. 审计字段类型和关联

- `ry-cloud` 中的 `create_by`、`update_by`、`remove_by` 统一使用 `BIGINT`，逻辑关联 `sys_user.user_id`。
- `ry_rental` 中的平台治理表和商户控制面表统一使用 `BIGINT`；平台写入时关联 `sys_user.user_id`，商户写入时关联 `ry_rental_merchant_user.merchant_user_id`。
- `ry_business` 中的租赁执行面审计字段统一使用 `BIGINT`，逻辑关联 `ry_rental.ry_rental_merchant_user.merchant_user_id`。跨数据库不建立物理外键，由服务端可信上下文校验。
- 匿名注册、系统任务和无法可靠匹配历史用户名的审计值保存 `NULL`；展示名称通过用户唯一编号查询，不把展示名称回写审计字段。
- Java `BaseEntity.createBy/updateBy` 以及显式 `removeBy` 使用 `Long`；Mapper 参数与 SQL 占位符保持数值类型，禁止继续使用用户名字符串。

## 5. 业务编码例外

`order_no`、`member_code`、`warehouse_code`、`product_code`、`sn_code` 等业务编码继续使用“订单编号”“商户编码”“仓库编码”“商品编码”“SN 编码”等专业名称，不改称“唯一编号”。链路 ID、UUID、外部系统 ID、物流单号和厂商序列号也保留各自的领域术语。

## 6. 变更规则

后续新增或修改功能时，技术字段按现有领域关系命名，语义文案按本规范书写。只有需求明确要求改变接口或数据库结构时，才允许另行设计版本化迁移和契约变更；单纯术语统一不得修改字段名或关联关系。
